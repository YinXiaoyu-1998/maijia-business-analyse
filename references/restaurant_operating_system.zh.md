# 连锁餐饮经营分析与持续学习框架

## 使用原则

把肯德基、麦当劳等头部连锁餐饮公开披露中的分析逻辑转化为麦家小馆可执行的经营框架。学习其指标关系和管理节奏，不直接照搬其绝对目标、成本结构或组织结论。

每项结论必须标明为以下一种：

- **事实**：由当前数据直接计算，能回溯到事实表。
- **诊断**：由多个事实支持的经营解释，同时写明反证或限制。
- **假设**：当前证据不足，需要到现场或补充数据验证。
- **行动**：明确责任人、期限、验证指标和目标值。

## 六层经营指标树

按“结果—驱动—场景—产品—经济性—可复制性”分析，避免只汇报营业额。

1. **规模结果**：营业收入、同店营业额、净增门店贡献、订单数、客单价。
2. **顾客驱动**：交易笔数/客流、客单价、新老客、消费频次、会员活跃与复购。
3. **场景渠道**：平常日与周末、餐段、堂食/外卖/自提、平台、数字化订单、天气和商圈事件。
4. **产品价格**：核心产品渗透、新品率、套餐率、折扣率、价格/折扣/产品组合/渠道组合。
5. **单店经济**：餐厅利润率、食材率、人工率、租金率、平台及配送成本率、贡献毛利、投资回收期。
6. **可复制与风险**：成熟周期、复购、差评、出餐/服务时长、缺货、食品安全、门店模型适配度。

缺少某层数据时，明确写“本期不可验证”，不得用上游结果替代下游原因。

## 核心分解公式

- 营业收入变化 = 同店营业额变化 + 净增门店贡献。没有新店资料时，仅报告同店或现有门店变化。
- 同店营业额变化近似由交易笔数变化与客单价变化共同驱动。金额归因优先使用可加总的桥接法，百分比仅作解释。
- 客单价变化 = 价格因素 + 折扣因素 + 产品组合因素 + 渠道组合因素。无法量化时列为待验证假设。
- 堂食金额 = 店内销售金额；外卖金额 = 营业收入 - 堂食金额。若存在自提、团购核销或其他渠道，先核对字段，避免把所有差额误记为外卖。
- 人效 = 营业额 / 对应时段出勤人数。优先使用工时口径；只有人数时必须注明“人次人效”。
- 前厅单人服务人效 = 对应时段服务客人数 / 前厅出勤人数。没有客人数时，不得用订单数冒充。
- 产品金额贡献率 = 产品销售金额 / 同渠道同范围销售总金额。
- 产品数量贡献率 = 产品销售数量 / 同渠道同范围销售总数量。

任何比率都在聚合后用分子除以分母重算；分母为零时留空并标注不可计算。

## 周报必做视角

按“总—分—总”呈现：先全体门店，再逐店诊断，最后汇总跨店差异与下周优先级。

1. **经营结果**：本周、环比、同比的营业额、订单、客单价；区分增长来自客流还是客单。
2. **日期类型**：周一至周四为平常日，周五至周日为周末；分别比较日均营业额、订单、客单价和增长贡献。若门店客观高峰日不同，保留统一口径用于横比，同时补充该店峰值日说明。
3. **渠道**：堂食与外卖的金额、数量、占比、环比/同比和增量贡献；识别外卖增量还是堂食迁移。
4. **产品**：全体与各店分别输出堂食、外卖 Top 10；至少包含金额、金额占比、数量、数量占比。另列上升/下降产品及其对收入变化的贡献。
5. **餐段时段**：早餐/午餐/晚餐/夜宵及小时段，展示上升和下降的主要时段；先回答“变化发生在哪里”，再验证原因。
6. **人员效率**：按门店、日期类型、餐段/时段展示前厅与后厨出勤人数/工时、营业额人效、前厅单人服务客数；收入与排班必须使用同一时间范围。
7. **顾客与服务**：会员、复购、缺货、履约、差评、评分等数据可得时纳入；差评按同类问题合并。
8. **单店经济**：有成本数据时才分析食材、人工、租金、渠道费用、贡献毛利和利润率；没有成本时只讨论收入效率，不声称利润改善。

## 增量与盈利护栏

每个增长动作同时回答：

1. 增加了多少交易笔数或营业额？
2. 增加了多少贡献毛利？若缺成本，明确需补充的数据。
3. 是否提升复购、评分或满意度？
4. 是否挤占堂食、其他时段、原价产品或其他渠道？

促销不能只看核销量。至少比较活动前后及可比门店/时段的增量、折扣成本、产品组合和复购信号。

## 根源分析：从现象到本质到现场

不要机械展示“5 Why”。对每类差评或经营异常使用以下链路：

1. **现象**：合并同类问题，列发生时间、渠道、产品、餐段、频次和影响。
2. **数据定位**：用订单、餐段、出餐时长、缺货、退款、排班等证据定位高发范围。
3. **现场还原**：核查当班人员、岗位分工、备货、设备、动线、标准执行和异常处置。
4. **管理本质**：判断是标准缺失、培训不到位、排班错配、检查失效、资源不足还是责任闭环断裂。
5. **整改与验证**：先止血，再修机制；用后续 8—10 天同类问题是否复发、评分、时长或抽检达标率验证。没有复发只能表述为“阶段性有效”，不能证明永久根治。

## SMART 行动卡

每个行动写成：`问题—证据—影响金额/频次—具体动作—责任人—验证指标与目标—截止日期—复盘日期`。

- 具体：指向岗位、流程、产品、渠道或时段。
- 可衡量：写清基线、目标、分子分母和数据源。
- 可实现：匹配门店资源和班次。
- 相关：直接对应已识别的经营驱动或顾客问题。
- 有时限：既有完成日，也有连续验证窗口。

## 日、周、月经营节奏

- **日报**：营业额、订单、客单、餐段、缺货、履约、差评、异常成本；输出 3 个异常、影响和当班动作。
- **周报**：同店分解、平常日/周末、渠道增量、产品四象限、促销收益、会员复购、人效、差评整改验证；输出 3—5 个经营假设及验证动作。
- **月报**：门店损益、店型模型、投资回报、成熟曲线、区域密度和预算预测；形成开店、整改、关停、菜单和预算决策。

## 持续学习闭环

新框架、新口径或新经验不得直接覆盖现有标准，按以下流程固化：

1. 记录来源、适用范围、日期和待解决问题；公开资料只作为外部参照。
2. 映射到六层指标树，避免重复指标或同名异义。
3. 写清公式、分子、分母、时间范围、门店范围、排除项和所需字段。
4. 用至少一个历史周期和一家门店试算，检查总分一致、渠道加总、比率重算和异常值。
5. 将结果与现场事实或责任人复核；区分相关性和因果性。
6. 只有验证通过后才加入标准周报；保留原口径及生效日期，禁止静默改写历史数据。
7. 连续 2—4 个周期复盘预测和行动效果；无效规则降级为假设或移除。

维护一个学习记录，至少包含：`日期、来源、学习点、指标层、口径变化、验证样本、结果、状态、负责人`。状态仅用“待验证、试运行、已固化、已废止”。

## 数据需求优先级

1. 必需：门店、营业日期、订单/交易、营业收入、店内销售、渠道、餐段/时段、产品金额与数量。
2. 人效：岗位、员工/班次、上班与下班时间或工时、对应时段客人数。
3. 盈利：食材、人工、租金、平台佣金、配送、营销费用和产品毛利。
4. 诊断增强：会员、新老客、复购、折扣活动、出餐时长、缺货、退款、差评原文及发生时间。

数据缺失时，先完成可验证层级，并在报告末尾列出“缺失数据—影响结论—补数责任人”。
